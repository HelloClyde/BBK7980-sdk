# V1.10 ABI 与原厂依据

分析源为官网下载的 `7980sj.exe`，SHA256：
`b9c4aa62cd9517859930620cdce5f7c6027120777926bb49e56989bb4e8d145c`。
原链接：https://down.eebbk.net/xzzx/7980/1/7980sj.exe 。
使用该文件中的系统镜像和原厂游戏，不以 A 系列地址代替 7980 系统接口。

## 原厂程序方式

炸弹小子、五子棋等游戏入口首先经固定地址 86ee 的跨程序区跳板调用
`02:4108`。原厂函数参数放在 09c3 起的参数区；部分参数由 A 传入。调用指令
后的三字节是“小端目标地址、程序区号”。这些字节不是顺序执行的 CPU 指令。

观察到的调用及 SDK 对应：

| 功能 | 原厂目标 | 依据 |
| --- | --- | --- |
| 事件初始化 | 02:4108 → 61bf | 原厂游戏入口 |
| 事件等待 | 02:410e → 63c8 | 五子棋、炸弹小子事件循环 |
| 键码转换 | 02:4120 → 6903 | 原厂事件循环处理 |
| 清空按键队列 | 02:43a5 → 517c | 原厂带 PHP/PLP 的短临界区 |
| 取字模 | 05:40d2 → 721d | 原厂 GBK 12/16/24 字模读取 |
| 文件 ID 查找 | 07:4024 → 67a7 | 系统初始化 font.bin 缓存也调用 67a7 |
| 文件长度 | 03:4072 → 46f2 | 原厂文件服务中的 32 位返回值 |
| 按位置读文件 | 07:4072 → 6d4f | 参数转入 6d92 文件读实现 |
| 创建/打开 | 07:4000 → 6435 | 原厂记事及电脑联机下载 |
| 流写入 | 07:4112 → 778b | 原厂记事及电脑联机下载 |
| 关闭提交 | 07:4036 → 680e | 原厂记事及电脑联机下载 |
| 流定位 | 07:4136 → 7aa7 | 原厂记事 |

| 提示音硬件参考 | 02:4264 → 5507/54ea | 原厂声音设置及按键提示音 |

源码中的目标均绑定本版本固件，并在原厂来宾代码中验证；不是声称已恢复
步步高内部完整头文件。摘要、交叉引用及函数段哈希见 `research/abi.json`。

## cc65 和原厂零页

原厂前台函数使用 X 管理零页软件栈，调用处通常为 a0；中断入口保存寄存器，
使用 `8c19` 指向的专用栈（本固件初始化为 f8），并在返回时恢复现场。

cc65 使用零页 80–9f。运行库在每次系统调用前保存 cc65 这 32 字节，恢复
原厂前台零页及 X；调用完成后保存原厂上下文并恢复 cc65 零页。32 位原厂
返回值先从原厂栈取出，再恢复 cc65。系统函数和中断使用的 a0–af 仍由内核管理。
参数区 09c3 起为内核共享区，SDK 接口不可重入。

这里没有 SEI/CLI，也不写 IENA。内核自己的短临界区保留。原厂事件等待进入
系统 WAI，由硬件事件唤醒，避免应用自行扫描 GPIO 或忙等计时器。

## 内存约束

| 区域 | 用途 |
| --- | --- |
| 4000–7ffe | 一个应用程序区，代码及常量/初始化数据镜像 |
| 程序区最后一字节 | 原厂 ADC 进位链校验补偿字节，由构建器填写 |
| 0080–009f | cc65 零页，系统调用时切换上下文 |
| a800–afff | DATA/BSS/NOINIT，共 2 KiB，链接器检查溢出 |
| 原厂堆中的独立 2 KiB 分配 | C 软件栈向下增长；启动时分配，正常返回时释放 |
| b000–bfff | 原厂 NAND 写入工作区，SDK 不在此放置 C 栈 |
| 0be0 起 7200 字节 | 原厂四灰阶显示缓冲 |

DATA 从程序区复制到 RAM，BSS 清零；桥接上下文单独放在 NOINIT，避免被
初始化覆盖。SDK 按原厂游戏方式调用 02:4132 初始化 c000–ffef 的堆，再经
02:4150 分配 C 栈。1.0 的固定 b000 区 C 栈在写入测试中发现会被原厂 NAND
缓冲覆盖，1.1 已修正；这也是不能只套用函数地址、忽略工作区约定的具体例子。
退出恢复原厂前台零页、X，调用 02:4162 释放 C 栈，恢复处理器状态并 RTS；Home 走原厂
系统处理路径。编译器尚未实现软件栈运行时溢出检测，应用必须控制递归和大局部数组。

原厂 C 栈、应用变量分布和中断现场的观察支持上述布局；真机 RAM 容量、
总线与时序仍需独立验证。SDK 没有将模拟器额外映射的 RAM 作为通用堆开放。

## 文件与打包

文件目录项定位复用原厂公式 `98c7 + file_id * 109`，传给原厂大小读取函数。
读文件参数为 ID、32 位偏移、RAM 指针、16 位长度。程序区里的字符串会因
系统调用切换 PRR 而不可见，故文件名先复制到 RAM。

原厂创建接口最后一个参数是八字节元数据的指针，不是立即数标志。已观察到
电脑联机下载以“模式3、文件名指针、八字节零元数据指针”创建文件；写入和关闭
分别到 778b/680e。SDK 写入时对 ROM 源数据分块复制，跨 NAND 页由原厂代码处理。
原厂定位码 2 为从当前位置后退，255 为从 EOF 后退；SDK 将公共 origin=2 映射为 255。

PSG 参考原厂 5507 的控制/音量设置以及 54ea 的音高寄存器写入。音符序列是
SDK 的实现，不复制原厂提示音中阻塞并关中断的延时循环。寄存器、频率公式依据
[Sitronix ST2202 原手册第 14 节](https://www.orientdisplay.com/wp-content/uploads/2022/08/ST2202A_v2.4.pdf)，
并与 [ST2204B 第 10 节](https://www.orientdisplay.com/wp-content/uploads/2022/08/ST2204B_v1.1.pdf)
及原厂实际写入交叉核对。实际芯片型号仍未通过真机拆机确认。

每 16 KiB 有效载荷执行原厂 ADC 进位链校验，最终累加器为 0。桌面数据在
第二个区：4000 是 8 字节 GBK 补空格名称，4010 是 32×32 两位图标。
PC 文件前置 128 字节 BJBBK.110 头，记录类型、分类、文件名、长度、sum32
和时间戳。前三十二字节与相同分类的原厂单入口游戏布局一致。
